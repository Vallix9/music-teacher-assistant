# Тестирование

## 1. Подход

Используется **pytest**. Каждый тест получает отдельную временную базу SQLite,
поэтому рабочая `instance/music_assistant.db` не изменяется. Тесты можно
запускать повторно в любом порядке.

```bash
python -m pytest
```

Ожидаемый результат:

```text
27 passed
```

## 2. Состав тестов

| Файл | Тестов | Что проверяется |
|------|:------:|-----------------|
| `tests/test_smoke.py` | 10 | вход, доступность всех страниц для трёх ролей, запрет `/users` не-админам, редиректы |
| `tests/test_crud.py` | 9 | CRUD классов, учеников, расписания, репертуара, материалов, мероприятий, пользователей; загрузка и удаление файла; запрет `.exe`; запрет изменений родителю |
| `tests/test_modules.py` | 7 | журнал (сохранение и обновление без дубликатов), карточка ученика, планы-конспекты, отчёты и CSV, права родителя |
| `tests/test_http.py` | 1 | реальный HTTP-сервер, CSRF-токен, POST без токена → 400, все разделы под учителем |
| **Итого** | **27** | |

## 3. Тест-кейсы

### Дымовые тесты (`test_smoke.py`)

| ID | Проверка | Ожидаемый результат |
|----|----------|---------------------|
| SM-01 | Вход администратора и обход 10 страниц | все страницы 200 |
| SM-02 | Вход учителя и обход 10 страниц | все страницы 200 |
| SM-03 | Вход родителя и обход 10 страниц | все страницы 200 |
| SM-04 | `/users` под администратором | 200 |
| SM-05 | `/users` под учителем | 403 |
| SM-06 | `/users` под родителем | 403 |
| SM-07–09 | Повторный GET `/login` авторизованным пользователем | 302 |
| SM-10 | GET `/` без авторизации | 302 на `/login` |

### CRUD (`test_crud.py`)

| ID | Проверка | Ожидаемый результат |
|----|----------|---------------------|
| CR-01 | Создание, изменение, удаление класса | записи меняются, класс удаляется |
| CR-02 | Создание, изменение, удаление ученика | данные сохраняются |
| CR-03 | Создание, изменение, удаление урока | день и номер обновляются |
| CR-04 | Создание и удаление произведения | запись удаляется |
| CR-05 | Загрузка файла, скачивание, удаление | файл на диске, ответ содержит содержимое, после удаления файла нет |
| CR-06 | Загрузка файла `.exe` | материал не создаётся |
| CR-07 | Создание и удаление мероприятия | запись удаляется |
| CR-08 | Создание, изменение, удаление пользователя | пароль проверяется, запись удаляется |
| CR-09 | Родитель пытается создать класс и открыть `/users` | 403, класс не создан |

### Модули (`test_modules.py`)

| ID | Проверка | Ожидаемый результат |
|----|----------|---------------------|
| MD-01 | Открытие журнала, конспектов, отчётов за разные периоды | 200 |
| MD-02 | Сохранение посещаемости и оценок | записи созданы |
| MD-03 | Повторное сохранение журнала | запись обновлена, дубликата нет |
| MD-04 | Карточка ученика | 200 |
| MD-05 | CRUD плана-конспекта | создание, просмотр, изменение, удаление |

| MD-07 | Родитель: журнал и отчёты открываются, сохранение запрещено | 200 / 403 |
| MD-08 | Родитель открывает карточку чужого ученика | 403 |

### HTTP и CSRF (`test_http.py`)

| ID | Проверка | Ожидаемый результат |
|----|----------|---------------------|
| HT-01 | GET `/login` по реальному HTTP | 200, форма и CSRF-токен есть |
| HT-02 | POST `/login` без токена | 400 |
| HT-03 | POST `/login` с токеном | 200, сессия создана |
| HT-04 | GET всех разделов под учителем | 200 |
| HT-05 | Отчёт по классу | содержит средний балл |

## 4. Ручная проверка интерфейса

| Проверка | Результат |
|----------|-----------|
| Тёмная тема на 10 страницах и странице входа | ✓ |
| Светлая тема на 10 страницах и странице входа | ✓ |
| Сохранение темы после перезагрузки и перехода между страницами | ✓ |
| Отсутствие горизонтальной прокрутки | ✓ |
| Ошибки в консоли браузера | не обнаружены |
| Дашборд родителя: 4 ребёнка, только свои классы и оценки | ✓ |
| Родитель не открывает чужой класс по прямому URL (403) | ✓ |
| Подмена `class_id` в отчётах/журнале/расписании | данные не раскрываются |
| Мобильная вёрстка (сайдбар, таблицы) | ✓ |

## 5. Что можно добавить

- Юнит-тесты отдельных функций (расчёт среднего балла и посещаемости).
- Проверка производительности на больших списках (пагинация).
- Автоматическая проверка вёрстки (Playwright/Selenium) и скриншоты.
- CI на GitHub Actions: запуск `pytest` при каждом push.
